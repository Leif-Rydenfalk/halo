# FINDING — every release-pack status is hand-authored, and item 5 is READY without its artifact

*halo Replica lane L4, 2026-09-05. A finding about the **release pack**, raised
from this lane because it owns fabrication and cannot write into `out/release/`
or `tools/`. Instrument: `../../tools/s_packstatus.py`.*

## 1. No status in the pack is computed

`spec/release-pack.json` gives each of the eleven artifacts a `status`, a
`reason`, an `evidence` line and — for ten of the eleven — **the `command` that
would prove it**.

`tools/gen_release_pack.py` **never runs any of them.** Its only `subprocess`
call is `git rev-parse --short HEAD`; every other use of `status` is counting
them, sorting by them, and rendering a badge. So all eleven are **hand-authored
literals**, against the workshop's own standing rule — *"`trust.json` is
COMPUTED here, never hand-authored"* — and against MISSION.md's requirement
that every item be *generated by a tool on this machine and graded PASS, never
asserted*.

## 2. Being hand-authored is not the same as being wrong — measured

I ran the recorded commands for every item that has a cheap one:

| item | asserted | its own command | verdict |
|---|---|---|---|
| 1 Gerbers, drill, netlist | PARTIAL | `check_fabset` → exit 1 | consistent |
| 3 BOM | **READY** | `check_bom_identity` → **exit 0**, 138 assertions, 0 fail | **agrees** |
| 4 Pick-and-place | **READY** | `check_cpl_rotations` → **exit 0**, 40/40 | **agrees** |
| 9 Test plan | PARTIAL | `gen_test_plan --selftest` → exit 0 | conservative |

**Item 3 deserves a correction to the debt register, not an accusation.**
`docs/VERIFICATION-DEBT.md` **V13** records *40 assertion failures over 24
lines* on that same BOM — a screw terminal block ordered as a 2.2 µF capacitor,
a $14.73 MEMS oscillator ordered as a 2.7 nH inductor. It now reports **138
assertions, 0 fail**. The defect was fixed and **V13 is stale**. Anyone reading
V13 today and relaying it would amplify a defect that no longer exists.

Six items have no cheap checker and were **not run** — several are heavy (a CAD
kernel build, a firmware build, a solver, a `--live` price pull another lane has
measured lying by 25×). They are reported **CANNOT DETERMINE**, never as a pass.
`s_packstatus.py audit` exits **2** for exactly that reason.

## 3. Item 5 is the proof that they drift

**`5 · Panel drawing, stackup and materials` — asserted READY.** Three problems:

- **Its evidence is a different board.** The `reason` field reads *"proven on
  the Ø31.87 mm round board"*. This board measures **25.6138 × 26.0000 mm**
  (`check_fabset`, `outline_has_extent`). Ø31.87 mm is the shell diameter.
- **The panel does not exist.** No file matching `*panel*` anywhere under
  `out/release/`.
- **Lane B1 already said so.** `out/release/board/STACKUP.md` §5 states plainly:
  *"**A panel.** `fab panel` has not been run on this outline. The factory lane
  reports a 3×3 panel clearing the minimum size on the Ø31.87 mm outline, which
  is the shell's diameter and not this board's."*

So the pack's own document contradicts the pack's own status, and nothing
compares them. **The statuses are right by maintenance, not by measurement, and
nothing tells anyone when one drifts.**

**In fairness to the panel claim itself:** B1 notes a Ø26.00 mm board
*"panelizes more easily"*, so the conclusion may well survive being redone. That
is not the point. A READY that would probably still be READY is still asserted.

## 4. What should change

1. `gen_release_pack.py` should **run each item's recorded `command`** and
   derive the status, or mark it CANNOT DETERMINE where it cannot. A recorded
   command that is never run is a decoration.
2. **An item with a missing deliverable cannot be READY**, whatever ran.
3. Item 5 → **PARTIAL** until `fab panel` runs on *this* outline, with the panel
   drawing in the pack.
4. **V13 in `docs/VERIFICATION-DEBT.md` should be marked closed** — measured
   0 failures today against its recorded 40.

## 5. The instrument

`s_packstatus.py` — verbs `audit`, `artifacts`, `selftest`. Exit code is the
verdict. Heavy commands are **off the allowlist on purpose**: running all eleven
on an 8 GB machine that has kernel-panicked twice this week would be its own
defect.

`selftest` **6/6**, with two breaks fired on purpose:

| break | result |
|---|---|
| artifact check never reports anything missing | **2 red** |
| a READY whose command exits non-zero is treated as fine | **1 red** |

The selftest carries two **fabricated** controls rather than relying on live
data: a made-up READY item pointing at a path that cannot exist, and a made-up
READY item whose command exits 3. Both must be caught. Without them the audit
could be a rubber stamp that happens to agree with a healthy pack — which,
today, it mostly is.

**This tool belongs in `tools/`, beside the checkers it runs.** It is in this
lane's directory only because `tools/` is held by another session and writing
there is an outage.
